# How-To Documentation Evaluation Rubric

**Purpose:** This rubric provides a structured framework for subject matter experts (SMEs) to evaluate how-to guides written for a beginner audience. The focus is on clarity, actionability, and the ability to guide a novice user to a successful outcome without prior knowledge.

## 1. Clarity and Simplicity of Language
*Is the language simple, direct, and free of jargon? Does it speak to a beginner?*

| Score | Description |
| :--- | :--- |
| **4 - Excellent** | Language is exceptionally simple and clear. All concepts are explained in plain terms. Acronyms and jargon are either avoided or explicitly defined on first use. |
| **3 - Good** | Language is mostly clear. It may contain occasional jargon or complex sentences that a beginner might need to re-read. |
| **2 - Needs Improvement** | Language is often too technical or assumes prior knowledge. A beginner would likely struggle to understand key parts of the guide. |
| **1 - Unsatisfactory** | Language is dense, academic, or heavily reliant on unexplained jargon, making it inaccessible to a novice. |

## 2. Step-by-Step Structure
*Are the instructions broken down into a logical sequence of small, distinct, and manageable steps?*

| Score | Description |
| :--- | :--- |
| **4 - Excellent** | The process is broken down into a clear, numbered sequence of small, easy-to-follow steps. Each step represents a single, distinct action. |
| **3 - Good** | The guide follows a sequential structure, but some steps might be too long or combine multiple actions, potentially confusing a beginner. |
| **2 - Needs Improvement** | The steps are poorly organized, out of sequence, or presented as large, intimidating blocks of text. The user cannot easily follow along. |
| **1 - Unsatisfactory** | There is no clear step-by-step structure. The guide is a narrative or a collection of disconnected facts. |

## 3. Goal and Prerequisite Clarity
*Is the end goal stated clearly at the beginning? Are all prerequisites, required tools, and setup instructions provided upfront?*

| Score | Description |
| :--- | :--- |
| **4 - Excellent** | The guide opens with a clear statement of what the user will achieve. All necessary tools, accounts, software versions, and setup steps are listed before the main instructions begin. |
| **3 - Good** | The goal is clear, and most prerequisites are listed. A user might discover a missing requirement mid-way through the process. |
| **2 - Needs Improvement** | The goal is vague, or prerequisites are missing or buried within the steps, leading to user frustration and interruption. |
| **1 - Unsatisfactory** | The guide fails to state the goal or mention any prerequisites, setting the user up for failure. |

## 4. Verification and Feedback
*Does the guide tell the user what to expect after each step? Is there a clear "success state" at the end?*

| Score | Description |
| :--- | :--- |
| **4 - Excellent** | The guide provides clear feedback for the user's actions (e.g., "You should see a confirmation message," "Your screen should now look like this"). It concludes with a clear way for the user to verify the entire process was successful. |
| **3 - Good** | The guide provides some feedback, but it may not be consistent for every step. The final success state is defined but could be clearer. |
| **2 - Needs Improvement** | The guide provides little to no feedback. The user is left guessing whether they have performed the steps correctly. |
| **1 - Unsatisfactory** | The user has no way of knowing if their actions are correct or if they have achieved the final goal. |

## 5. Use of Visuals and Concrete Examples
*Are there sufficient, high-quality visuals (screenshots, GIFs) and copy-paste-ready examples to support the instructions?*

| Score | Description |
| :--- | :--- |
| **4 - Excellent** | Visuals are used effectively to illustrate key steps and reduce ambiguity. Code snippets and commands are complete, correct, and easy to copy. |
| **3 - Good** | Visuals and examples are present and helpful but could be used more consistently or be of higher quality (e.g., blurry screenshots, partial code snippets). |
| **2 - Needs Improvement** | The guide relies almost entirely on text where visuals would be essential for a beginner. Examples are missing or incomplete. |
| **1 - Unsatisfactory** | The guide contains no visuals or examples, making it extremely difficult for a beginner to follow. |

## 6. Troubleshooting and Common Issues
*Does the guide anticipate common problems a beginner might face and offer simple solutions?*

| Score | Description |
| :--- | :--- |
| **4 - Excellent** | A dedicated "Troubleshooting" or "Common Errors" section is included, or potential issues are addressed proactively within the steps (e.g., "If you see this error, it means..."). |
| **3 - Good** | The guide acknowledges that things might go wrong but provides only limited guidance on how to resolve issues. |
| **2 - Needs Improvement** | The guide follows a "happy path" only and does not address any potential errors or points of confusion. |
| **1 - Unsatisfactory** | The guide is not only a "happy path" but may contain steps that are known to be error-prone without any warning. |

## Overall Assessment
Final Score is out of 24.
